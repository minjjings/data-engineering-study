## 오늘의 학습 목표

- 원하는 날짜만 재실행하는 운영 절차를 완성한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |

## 1장. 개념 이해하기

catchup은 예약 구간 중 실행되지 않은 과거 구간을 따라잡는 설정이고 backfill은 지정한 과거 범위를 재처리하는 작업이다. 켜기만 하면 무제한 병렬 실행이 안전해지는 것은 아니며 동시 실행과 외부 API 제한을 고려한다.

오늘은 한 날짜에서 시작해 3개 구간으로 늘린다. 자동 증분 상태와 수동 재처리 상태를 분리하고, 실패 후 어디부터 다시 실행할지 문서로 남긴다. CLI 문법은 설치한 Airflow 3 버전의 --help를 먼저 확인한다.

## 2장. 실습 준비

Airflow 3 계열은 공식 Docker Compose 안내로 별도 `infra/airflow/` 환경을 만든다. 루트 Compose는 PostgreSQL 실습용으로 유지한다. 해당 디렉터리에서 공식 compose 파일을 받고 `docker compose -p de-airflow up airflow-init`, `docker compose -p de-airflow up -d` 순서로 실행한다. 실제 사용 이미지 태그·설정·접속 방법을 기록한다. DAG는 루트 dags에 작성하고 공식 구성의 dags 마운트 경로에 복사한다. 컨테이너 CLI는 `docker compose -p de-airflow exec airflow-scheduler ...`로 실행한다. 아래 Airflow 명령은 그 컨테이너 안 기준이다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 26](../day26/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```bash
airflow dags test --help
airflow dags test market_demo 2026-10-26
airflow backfill create --help
```

**예상 결과와 확인 기준:** 단일 날짜 DAG 테스트의 성공·실패와 해당 처리 구간을 확인한다. test 명령은 실제 Task 코드를 실행하므로 학습용 DB만 연결한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 날짜 3개를 순서대로 처리하고 실행별 구간·건수를 표로 만든다.
2. 중간 날짜 하나를 재실행해 목표 상태가 변하지 않는지 확인한다.
3. 환경 시작·DAG 복사·실행·실패 Task 재시도·종료 절차를 기록한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day30/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

준비 항목에서 지정한 환경의 CLI로 실행한다. 호스트와 컨테이너의 경로·네트워크·설치 패키지를 구분한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
