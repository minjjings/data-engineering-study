## 1장. 개념 이해하기

로그는 프로그램이 무엇을 처리했고 어디에서 실패했는지 설명하는 기록이다. 배치 id·입력 건수·정상·무효·중복 건수를 같이 남기면 원본과 결과를 연결할 수 있다. 비밀번호나 전체 인증 응답은 로그에 넣지 않는다.

예외를 무조건 삼키면 실패한 실행이 성공처럼 보인다. 예상한 행 단위 오류는 사유와 원본을 격리하고, 파일 전체 손상이나 DB 연결 실패처럼 진행할 수 없는 문제는 작업을 실패시킨다. 경로와 연결값은 환경변수나 인자로 분리한다.

## 2장. 실습 준비

Python 3.11 이상을 사용하고 버전을 기록한다. 루트에서 `python -m venv .venv`로 가상환경을 만들고, 이후 Python 블록은 `dayNN/practice.py`로 저장해 `.\.venv\Scripts\python.exe .\dayNN\practice.py`로 실행한다. Python 표준 라이브러리부터 사용하며 Day 1 코드·샘플은 보존한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 16](../day16/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
import logging
import os

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
input_path = os.environ.get("DE_INPUT", "day01/data/raw.json")
logging.info("batch_id=local-001 input=%s", input_path)
rejected = {"row": {"close": "N/A"}, "reason": "invalid_price"}
logging.warning("batch_id=local-001 reason=%s", rejected["reason"])
```

**예상 결과와 확인 기준:** INFO에 입력 경로, WARNING에 실패 사유가 나온다. 이 예제는 로그 구조를 보여주며 실제 건수는 수집 코드에 연결해야 한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 정상·무효·중복 건수의 합이 원본 건수와 같은지 로그에 남긴다.
2. rejected.json에 원본 행·사유·batch_id를 저장한다.
3. 환경변수 DE_INPUT으로 파일을 바꾸고 없는 파일은 비정상 종료하도록 만든다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day19/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

예제에서 지정한 Python 환경·현재 경로·패키지 버전을 확인한다. Task 내부나 이전 코드에 합치는 부분 예제는 주석의 실행 문맥을 먼저 준비한다.
