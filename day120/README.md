# Day 120. 최종 리뷰와 다음 학습 계획

**24주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 119](../day119/README.md)

이번 주에는 **통합 검증·복구·문서화와 최종 리뷰** 내용을 다룬다. 오늘은 설계 선택과 검증 근거를 자신의 말로 설명한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 설계 선택과 검증 근거를 자신의 말로 설명한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

완료는 파일 존재가 아니라 요구한 동작을 재현하고 설명할 수 있다는 뜻이다. 성공한 경로와 함께 제약·미검증 범위·운영 비용도 기록한다. 현재 한계를 근거로 다음 학습과 실험을 고른다.

## 2장. 실습 준비

23주의 필수 배치가 실행되어야 한다. 입력·기대 키·가격을 고정하고 정상·오류·과거 구간을 구분한다. 기존 공개 결과는 보존하며 별도 batch_id로 실험한다. docs/project에는 처음 보는 사람이 따라 할 수 있는 실행 안내와 검증 근거를 작성한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 116](../day116/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
최종 설명 순서
1. 분석 질문과 업무 키
2. Raw·정제·DW·마트의 책임
3. 멱등성·지연 수정·공개 경계
4. 정상·반복·오류·복구 검증
5. 실행 시간·비용·확장 한계
6. 남은 범위와 다음 실험
```

**예상 결과와 확인 기준:** 5~10분 설명과 문서 링크로 설계·결과·한계를 검토할 수 있다. 미검증 항목은 완료로 표시하지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 실행 안내·검증 결과표·회고를 정리한다.
2. 초기 목표와 직접 설명·실행할 수 있는 항목을 비교한다.
3. 보완할 주제 세 개와 구체적인 다음 실험을 정한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day120/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.

## 오늘의 완료 기준

- [ ] 핵심 개념을 오늘 예제에 연결해 설명했다.
- [ ] 따라 하기 예제의 실제 결과를 예상 결과와 비교했다.
- [ ] 직접 해볼 과제 세 개를 구현·실행하고 근거를 남겼다.
- [ ] 오류 또는 남은 한계를 기록하고 다음 단계의 선행 조건을 확인했다.

**생각해볼 질문:** 규모가 열 배가 되면 가장 먼저 어디를 측정하고 바꿀까?
