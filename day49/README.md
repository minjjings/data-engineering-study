# Day 49. IAM 최소 권한과 허용 범위 검증

**10주 차 · 주간 4일차 | 약 90~120분**

이번 주에는 **S3 데이터 레이크와 접근 권한** 내용을 다룬다. 오늘은 특정 prefix만 읽고 쓸 수 있는 권한을 설계한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 특정 prefix만 읽고 쓸 수 있는 권한을 설계한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

ListBucket은 버킷 ARN, GetObject·PutObject는 객체 ARN을 대상으로 한다. 필요한 동작과 저장 위치를 나누어 정한다. 다른 정책에서 넓은 권한을 허용하고 있다면 이 정책만으로 접근이 제한되지는 않는다.

## 2장. 실습 준비

AWS 계정·리전·예산 알림과 AWS CLI v2를 준비한다. PowerShell에서 인증한 프로필과 AWS_PROFILE, AWS_DEFAULT_REGION=ap-northeast-2, DE_BUCKET 환경변수를 설정한다. DE_BUCKET에는 본인이 소유한 실습용 버킷 이름을 넣는다. 버킷 이름은 전역에서 유일해야 한다. 실제 AWS 실습은 비용이 발생할 수 있다. 계정이 없다면 로컬 파일·권한 설계까지 진행하고 클라우드 실행은 미완료로 기록한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 46](../day46/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {"Effect": "Allow", "Action": "s3:ListBucket",
     "Resource": "arn:aws:s3:::YOUR_BUCKET",
     "Condition": {"StringLike": {"s3:prefix": ["raw/market/*"]}}},
    {"Effect": "Allow", "Action": ["s3:GetObject", "s3:PutObject"],
     "Resource": "arn:aws:s3:::YOUR_BUCKET/raw/market/*"}
  ]
}
```

**예상 결과와 확인 기준:** YOUR_BUCKET을 실제 이름으로 바꾸는 정책 설계 예다. 작성만으로 적용되지는 않으며 별도 실습 역할에서 검증한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 기존 역할의 정책을 확인하고 관리 역할과 제한된 검증 역할을 구분한다.
2. 제한 역할로 대상 prefix 읽기 성공과 다른 prefix 쓰기 거부를 확인한다.
3. Athena·Glue에는 Catalog와 결과 경로 권한도 필요한 이유를 기록한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day49/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

YOUR_BUCKET 같은 예시 이름을 본인의 실습 환경 값으로 바꾼다. JSON 작성과 실제 서비스 적용·검증을 구분한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
