## 1장. 개념 이해하기

at-least-once는 다시 전달될 수 있음을 받아들이고 누락을 줄이는 방식이다. 정확히 한 번이라는 표현은 입력·계산·출력의 어디까지 보장하는지 범위를 밝혀야 한다. Kafka가 보관한 이벤트도 retention 이후에는 재생할 수 없다.

## 2장. 실습 준비

Day81에서 infra/kafka/compose.yaml을 만들고 `docker compose -p de-stream -f infra/kafka/compose.yaml up -d`로 실행한다. 호스트 Python·Spark는 localhost:9092, 같은 Compose의 Connect는 kafka:29092를 사용한다. CLI 예제는 PowerShell에서 실행하며 도구 경로는 /opt/kafka/bin/이다. Python 예제는 별도 가상환경에 confluent-kafka를 설치하고 사용 버전을 기록한다. 이 주차에서는 매일 Topic을 지우거나 offset을 초기화하지 않는다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 81](../day81/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
저장 전 실패 → offset 미커밋 → 재전달
저장 후 커밋 전 실패 → 재전달 → event_id로 중복 방지
커밋 후 저장 실패 → 재전달되지 않을 수 있음 → 유실 위험
```

**예상 결과와 확인 기준:** 각 경우를 실제Consumer 로그·offset·DB 상태로 확인해야 하며 문장만으로 완료 처리하지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. Producer·Consumer·이벤트 계약과 실행 명령을 정리한다.
2. 정상·중복·저장 후 중단·Consumer 재시작을 실험한다.
3. retention과복제계수1의 한계, 토픽·볼륨 유지와 종료 방법을 기록한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day85/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
