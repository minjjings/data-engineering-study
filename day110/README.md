# Day 110. 새 환경 재현과 22주 리뷰

**22주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 109](../day109/README.md) · [Day 111 →](../day111/README.md)

이번 주에는 **테스트·CI/CD와 재현 가능한 환경** 내용을 다룬다. 오늘은 숨은 로컬 상태 없이 실행 안내만으로 동작시킨다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 숨은 로컬 상태 없이 실행 안내만으로 동작시킨다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

재현성에는 패키지 외에도 환경변수·초기 SQL·경로·실행 순서가 포함된다. 기존 볼륨의 표나 수동 설정에 의존하면 새 환경에서 실패한다. 학습 DB를 지우지 말고 별도 이름과 포트로 재현한다.

## 2장. 실습 준비

4~5주 src와 tests, dbt 프로젝트가 준비되어 있어야 한다. 루트 requirements.txt에 실제 필요한 패키지와 버전을 정리한다. CI는 GitHub Actions의 독립 PostgreSQL17 서비스를 사용하고 로컬 실습DB·AWS 계정에 연결하지 않는다. workflow는 작성·로컬 확인 후 사용자가 push했을 때 원격 실행 결과를 확인한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 106](../day106/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```powershell
# 분리된 Compose에 충돌 없는 포트와 컨테이너 이름을 설정한 뒤 실행한다.
docker compose -p de-reproduce -f infra/reproduce/compose.yaml config --quiet
docker compose -p de-reproduce -f infra/reproduce/compose.yaml up -d
```

**예상 결과와 확인 기준:** 분리된 Compose는 직접 작성한다. 기존 Compose는 container_name이 고정되어 project 이름만 바꾸면 충돌한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 별도 환경에서 초기화부터 샘플 실행까지 진행한다.
2. CI·배포·복구·재현 문서를 다시 따라가며 빠진 단계를 고친다.
3. 테스트 범위와 아직 검증하지 않은 경로를 명시한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day110/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

명령은 저장소 루트의 PowerShell에서 실행한다. 환경변수와 컨테이너 상태를 먼저 확인하고 오류 전문을 기록한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
