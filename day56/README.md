## 1장. 개념 이해하기

Glue에는 코드뿐 아니라 실행 역할·런타임·입출력 위치가 필요하다. 로컬 상대 경로는 클라우드에 없으므로 S3 키를 인자로 받는다. 작업 성공 상태와 결과의 정확성은 따로 확인한다.

## 2장. 실습 준비

S3·Catalog·로컬 PostgreSQL을 사용한다. Glue Python shell 작업을 작은 JSON Lines로 한 번 실행한다. 실습용 역할에 입력·스크립트 읽기, 출력 prefix 쓰기, 로그 권한을 부여한다. Python 런타임·타임아웃·실행 용량을 기록한다. Redshift는 역할 비교까지 필수이며 생성은 선택 과제다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 56](../day56/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
import sys
import boto3

bucket = sys.argv[sys.argv.index("--bucket") + 1]
key = sys.argv[sys.argv.index("--input_key") + 1]
body = boto3.client("s3").get_object(Bucket=bucket, Key=key)["Body"].read()
print({"input_bytes": len(body), "lines": len(body.splitlines())})
```

**예상 결과와 확인 기준:** --bucket과 --input_key에 Day 48 파일을 지정하면 로그에 lines=4가 표시된다. 아직 정제 출력은 만들지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

2. 짧은 타임아웃과 작은 실행 용량으로 한 번 실행한다.
3. 입력 키·JobRunId·시간·로그·비용 확인 위치를 남긴다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day56/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

예제에서 지정한 Python 환경·현재 경로·패키지 버전을 확인한다. Task 내부나 이전 코드에 합치는 부분 예제는 주석의 실행 문맥을 먼저 준비한다.
