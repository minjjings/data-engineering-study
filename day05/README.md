## 1장. 개념 이해하기

품질 규칙은 무엇을 사용할 수 있는 데이터로 볼지 명시한 약속이다. 오늘은 종목·거래일이 있고 가격이 양수인 행을 정상으로 본다. 문자열을 곧바로 숫자로 바꾸면 N/A에서 실패하므로 CASE 안에서 형식을 확인한 뒤 변환한다.

멱등성은 같은 논리 입력을 여러 번 적용해도 목표 상태가 같다는 성질이다. SELECT를 두 번 실행해 결과가 같은 것과 INSERT를 두 번 해도 중복되지 않는 것은 다른 문제다. 오늘은 정제 결과를 검증하고, 저장 단계의 멱등성은 이후 UPSERT로 구현한다.

## 2장. 실습 준비

Day 1·2의 Python과 PostgreSQL 환경을 사용한다. 저장소 최상위 PowerShell에서 `docker compose up -d` 후 `docker exec -it de-postgres psql -U de_user -d market_db`로 접속한다. SQL 블록은 psql에서 실행한다. 원본 5건을 유지하고, 예제의 임시 테이블은 현재 접속에서만 사용한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 1](../day01/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```sql
WITH parsed AS (
    SELECT *, CASE
        WHEN close_price ~ '^[0-9]+([.][0-9]+)?$'
        THEN close_price::numeric END AS price
    FROM raw_market_prices
), ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY symbol, trade_date
        ORDER BY collected_at DESC, id DESC
    ) AS rn
    FROM parsed
    WHERE price > 0 AND symbol IS NOT NULL AND trade_date IS NOT NULL
)
SELECT symbol, trade_date, price FROM ranked
WHERE rn = 1 ORDER BY symbol, trade_date;
```

**예상 결과와 확인 기준:** 최초 5건에서는 QQQ 620.50, SPY 680.20 두 행이다. 여기서는 정상 가격을 먼저 남긴 뒤 최신 행을 고른다. Raw는 5건 그대로다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. Day 1과 Day 2의 입력 건수 차이(4건·5건)와 공통 정제 결과(2건)를 정리한다.
2. 위 SQL을 두 번 실행해 결과를 비교하고 저장 멱등성까지 증명한 것인지 구분한다.
3. 1주 회고에 ETL·ELT, JOIN, Watermark, 정상 가격 선택 기준을 예제로 설명한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day05/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

SQL 실행 위치를 확인한다. 일반 PostgreSQL SQL은 psql에서, Athena SQL은 Athena에서, Jinja가 있는 모델 SQL은 dbt 모델 파일에서 실행한다. TEMP 테이블은 생성한 연결에서만 보인다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
