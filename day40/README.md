이번 주에는 **dbt 테스트와 문서화** 내용을 다룬다. 오늘은 모델의 의미와 품질 규칙을 다른 사람이 찾을 수 있게 만든다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 모델의 의미와 품질 규칙을 다른 사람이 찾을 수 있게 만든다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |

## 1장. 개념 이해하기

lineage는 원천에서 모델까지의 의존 관계다. SQL만 있으면 계산 방법은 볼 수 있지만 왜 그 규칙을 선택했는지는 알기 어렵다. grain·가격 단위·NULL 정책·최신 선택 기준·실패 시 조치를 모델과 컬럼 설명에 남긴다.

## 2장. 실습 준비

Day 31~35 dbt 프로젝트와 PostgreSQL을 사용한다. YAML은 models 아래에, singular SQL 테스트는 tests 아래에 작성한다. 모델 이름은 stg_prices·int_latest_prices·mart_symbol_prices를 기준으로 한다. Raw 변경 실험은 전용 배치/트랜잭션에서 수행해 최초 샘플을 보존한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 36](../day36/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```bash
dbt build --select +mart_symbol_prices
dbt docs generate
dbt docs serve --port 8081
```

**예상 결과와 확인 기준:** 테스트를 포함한 build 결과와 문서 화면을 확인한다. serve는 로컬 프로세스이므로 종료할 때 Ctrl+C를 누른다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 주요 3개 모델과 컬럼 설명을 YAML에 작성한다.
2. source부터 mart까지 의존 경로와 테스트 위치를 화면에서 확인한다.
3. 8주 결과에 실패 사례·수정·통과·freshness 해석을 정리한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day40/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

준비 항목에서 지정한 환경의 CLI로 실행한다. 호스트와 컨테이너의 경로·네트워크·설치 패키지를 구분한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
