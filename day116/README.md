# Day 116. 정상 실행과 동일 입력 재실행

이번 주에는 **통합 검증·복구·문서화와 최종 리뷰** 내용을 다룬다. 오늘은 키·값·공개 상태로 멱등성을 검증한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 키·값·공개 상태로 멱등성을 검증한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 1 | 개념과 준비 항목 확인 | 20분 |

## 1장. 개념 이해하기

정상 결과를 기준선으로 저장하고 같은 구간을 다시 실행한다. 건수만 보면 누락과 초과가 상쇄되는 경우를 놓친다. 업무 키·가격·중복·공개 배치 상태를 함께 확인한다.

## 2장. 실습 준비

23주의 필수 배치가 실행되어야 한다. 입력·기대 키·가격을 고정하고 정상·오류·과거 구간을 구분한다. 기존 공개 결과는 보존하며 별도 batch_id로 실험한다. docs/project에는 처음 보는 사람이 따라 할 수 있는 실행 안내와 검증 근거를 작성한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 116](../day116/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```sql
-- 실제목표표이름에맞춰별도실습스키마에서실행한다.
CREATE TABLE dw_lab.replay_baseline AS SELECT * FROM dw_lab.fact_price;
-- 동일배치를재실행한뒤양방향차이를확인한다.
SELECT symbol, trade_date, close_price FROM dw_lab.replay_baseline
EXCEPT
SELECT symbol, trade_date, close_price FROM dw_lab.fact_price;
```

**예상 결과와 확인 기준:** 양방향 EXCEPT 결과가 모두 0행이어야 한다. baseline은 최초 한 번만 만들고 검증 증거를 덮어쓰지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 정상 입력·최종 키·가격·공개 batch_id를 보관한다.
2. 같은 구간을 두 번 실행하고 양방향 차이와 중복을 확인한다.
3. Raw 이력과 최종 표가 서로 다른 증가 정책을 가질 수 있는 이유를 설명한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day116/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

SQL 실행 위치를 확인한다. 일반 PostgreSQL SQL은 psql에서, Athena SQL은 Athena에서, Jinja가 있는 모델 SQL은 dbt 모델 파일에서 실행한다. TEMP 테이블은 생성한 연결에서만 보인다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
