## 1장. 개념 이해하기

수동 명령이 성공해도 스케줄러 안의 경로·의존성·네트워크는 다를 수 있다. 같은 실행 구간을 모든 Task에 전달하고 품질 검사 뒤 공개한다. Athena로 S3 정제 결과와 DW의 키·집계를 대사한다.

## 2장. 실습 준비

기존 src·Spark·DW·dbt·Airflow를 사용한다. 설계는 docs/project에 모으고 가상 시장 가격 예제를 확장한다. 최소 배치 경로부터 검증하고 CDC는 별도 대상 표의 확장 경로로 둔다. 각 day 예제의 설계를 실제 코드로 연결하는 단계다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 111](../day111/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
# 실제 Task 객체가 정의된 DAG 내부에서 연결한다.
def wire_batch(collect, upload_raw, spark_clean, validate_files,
               load_dw, dbt_build, publish):
    collect >> upload_raw >> spark_clean >> validate_files
    validate_files >> load_dw >> dbt_build >> publish
```

**예상 결과와 확인 기준:** 실제 Task 객체로 의존성 함수를 호출하고 구간 하나를 실행한다. 함수 정의만으로 DAG가 생성되지는 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 모든 Task에 batch_id·시작·종료 인자를 전달한다.
2. 실제 Parquet 위치를 Catalog에 등록해 Athena·DW를 비교한다.
3. 실패를 한 번 주입해 공개 차단과 재실행을 확인한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day114/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

예제에서 지정한 Python 환경·현재 경로·패키지 버전을 확인한다. Task 내부나 이전 코드에 합치는 부분 예제는 주석의 실행 문맥을 먼저 준비한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
