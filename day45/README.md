# Day 45. 증분 복구와 9주 리뷰

**9주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 44](../day44/README.md) · [Day 46 →](../day46/README.md)

이번 주에는 **dbt 증분 모델과 Airflow 연결** 내용을 다룬다. 오늘은 변경·지연·실패 시나리오를 통합 검증한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 변경·지연·실패 시나리오를 통합 검증한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

증분 처리는 빠른 실행과 올바른 결과를 함께 요구한다. 오늘은 같은 입력, 최근 수정, 범위 밖 지연, 테스트 실패를 각각 확인한다. 모델 변경으로 과거 전체 결과가 달라지면 단순 재시도 대신 재구축이 필요할 수 있다.

## 2장. 실습 준비

기존 dbt 프로젝트를 사용하며 `seeds/incremental_input.csv`에 symbol,trade_date,close_price 헤더와 QQQ,2026-10-26,620.50 및 SPY,2026-10-26,680.20 두 행을 준비한다. Day 41~44에서는 이 seed를 바꾸며 실험한다. Airflow 연동은 Worker 이미지 안에도 같은 dbt 어댑터·프로젝트·profile을 배치해야 한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 41](../day41/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```bash
dbt seed --select incremental_input
dbt build --select +fct_prices_incremental
dbt test --select fct_prices_incremental
```

**예상 결과와 확인 기준:** 명령 성공뿐 아니라 키·가격·양방향 대사로 결과를 확인한다. 테스트를 정의하지 않았다면 test 명령만으로 검증된 것으로 보지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 4개 시나리오별 입력·예상 결과·실제 결과를 기록한다.
2. Airflow 실패 Task 재실행과 full-refresh 복구 경로를 각각 수행한다.
3. 증분 전략·겹치는 범위·한계·운영 명령을 9주 문서로 정리한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day45/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

준비 항목에서 지정한 환경의 CLI로 실행한다. 호스트와 컨테이너의 경로·네트워크·설치 패키지를 구분한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
