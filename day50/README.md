# Day 50. 보관 기간·복원과 10주 리뷰

**10주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 49](../day49/README.md) · [Day 51 →](../day51/README.md)

이번 주에는 **S3 데이터 레이크와 접근 권한** 내용을 다룬다. 오늘은 재처리에 필요한 원본을 유지하며 저장 비용을 관리한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 재처리에 필요한 원본을 유지하며 저장 비용을 관리한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

라이프사이클은 객체의 보관 기간과 저장 등급을 관리한다. Raw를 너무 빨리 지우면 규칙 변경 후 재처리가 어려워진다. 버전 관리를 켰다면 현재 객체뿐 아니라 과거 버전도 비용과 정리 대상에 포함한다.

## 2장. 실습 준비

AWS 계정·리전·예산 알림과 AWS CLI v2를 준비한다. PowerShell에서 인증한 프로필과 AWS_PROFILE, AWS_DEFAULT_REGION=ap-northeast-2, DE_BUCKET 환경변수를 설정한다. DE_BUCKET에는 본인이 소유한 실습용 버킷 이름을 넣는다. 버킷 이름은 전역에서 유일해야 한다. 실제 AWS 실습은 비용이 발생할 수 있다. 계정이 없다면 로컬 파일·권한 설계까지 진행하고 클라우드 실행은 미완료로 기록한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 46](../day46/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```powershell
aws s3 cp .\day48\market.jsonl "s3://$env:DE_BUCKET/raw/market/ingest_date=2026-10-30/part-000.jsonl"
aws s3 ls "s3://$env:DE_BUCKET/raw/market/" --recursive
aws s3api get-bucket-versioning --bucket $env:DE_BUCKET
```

**예상 결과와 확인 기준:** 다른 날짜 키 두 곳에 같은 Raw가 각각 4행씩 저장된다. 재수집 예제이므로 분석에서 단순 합산하지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. Raw·curated·쿼리 결과의 보관 기간을 따로 정한다.
2. 같은 키 덮어쓰기와 다른 키 저장의 복원 방법을 비교한다.
3. 권한·경로·건수·비용 확인과 나중에 정리할 키 목록을 기록한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day50/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

명령은 저장소 루트의 PowerShell에서 실행한다. 환경변수와 컨테이너 상태를 먼저 확인하고 오류 전문을 기록한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.

## 오늘의 완료 기준

- [ ] 따라 하기 예제의 실제 결과를 예상 결과와 비교했다.
- [ ] 직접 해볼 과제 세 개를 구현·실행하고 근거를 남겼다.
- [ ] 오류 또는 남은 한계를 기록하고 다음 단계의 선행 조건을 확인했다.
