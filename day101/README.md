## 오늘의 학습 목표

- 수집·변환·검증·공개의 로그를 같은 실행으로 연결한다.

- 직접 작성한 과제와 실행 근거를 남긴다.

## 1장. 개념 이해하기

구조화 로그는 시간·수준·작업·batch_id·건수 같은 필드를 일정하게 남긴다. 문장만 저장하는 것보다 검색과 집계가 쉽다. run_id는 실행 시도, batch_id는 논리 입력 구간을 나타내도록 구분하면 재시도도 추적할 수 있다.

## 2장. 실습 준비

로그는 기존 배치의 batch_id를 기준으로 연결한다. Day102에서 PostgreSQL ops_lab.pipeline_runs를 만들고 실행 지표를 저장한다. Day103에서 별도 Grafana 환경을 추가해 PostgreSQL을 조회한다. Prometheus 추가는 선택 과제로 두고 이번 주는 하나의 지표 저장 경로를 완성한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 101](../day101/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
import json
from datetime import datetime, timezone

record = {"timestamp": datetime.now(timezone.utc).isoformat(),
          "level": "INFO", "batch_id": "2026-10-26", "run_id": "attempt-1",
          "task": "validate", "input_rows": 4, "output_rows": 4,
          "status": "success"}
print(json.dumps(record))
```

**예상 결과와 확인 기준:** 한 줄 JSON 로그가 출력된다. 실제 프로그램에서 단계별 값으로 교체해야 추적에 사용할 수 있다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 기존 CLI와 DAG에서 같은 batch_id를 모든 단계 로그에 전달한다.
2. 정상·재시도·실패 로그를 모아 한 실행의 순서를 복원한다.
3. 비밀번호·DSN 전체·불필요한 원문을 로그에 남기지 않도록 확인한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day101/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

예제에서 지정한 Python 환경·현재 경로·패키지 버전을 확인한다. Task 내부나 이전 코드에 합치는 부분 예제는 주석의 실행 문맥을 먼저 준비한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
