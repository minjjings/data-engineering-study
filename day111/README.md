# Day 111. 요구사항과 최소 분석 질문

**23주 차 · 주간 1일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 110](../day110/README.md) · [Day 112 →](../day112/README.md)

이번 주에는 **통합 프로젝트 최소 배치와 스트리밍 확장** 내용을 다룬다. 오늘은 완료 여부를 판정할 수 있는 범위를 정한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 완료 여부를 판정할 수 있는 범위를 정한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

먼저 대상 종목·처리 주기·날짜 범위와 분석 질문을 정한다. 도구 목록보다 답할 질문과 검증 기준이 우선이다. 정상·재실행·지연·실패의 성공 기준을 관측할 수 있는 값과 상태로 쓴다.

## 2장. 실습 준비

기존 src·Spark·DW·dbt·Airflow를 사용한다. 설계는 docs/project에 모으고 가상 시장 가격 예제를 확장한다. 최소 배치 경로부터 검증하고 CDC는 별도 대상 표의 확장 경로로 둔다. 각 day 예제의 설계를 실제 코드로 연결하는 단계다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 111](../day111/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
분석 질문: 종목별 마지막 정상 가격과 관측 거래일 수는?
입력: 고정 seed의 가상 가격 JSON Lines
업무 키: symbol + trade_date
필수: 수집 → S3 Raw → Spark Parquet → PostgreSQL DW → dbt mart
실행 관리: Airflow, 품질 검사 뒤 공개
선택: CDC → Kafka → 별도 대상 표
```

**예상 결과와 확인 기준:** 요구사항 한 장에 입력·출력·키·주기·품질·복구 기준을 담는다. 구현 여부는 이후 실행으로 확인한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 필수·선택 범위를 나누어 2주에 끝낼 크기로 정한다.
2. 고정 입력과 오류 주입 입력을 나누고 예상 키·값을 계산한다.
3. 복구 목표·비용 상한·실습 종료 조건을 정한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day111/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
