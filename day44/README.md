## 1장. 개념 이해하기

스케줄러가 호스트의 가상환경이나 파일을 자동으로 볼 수는 없다. Worker에 dbt·어댑터·프로젝트를 함께 배치하고 컨테이너용 DB 주소로 profile을 구성해야 한다. dbt 명령의 비정상 종료를 Task 실패로 전달한다.

## 2장. 실습 준비

기존 dbt 프로젝트를 사용하며 `seeds/incremental_input.csv`에 symbol,trade_date,close_price 헤더와 QQQ,2026-10-26,620.50 및 SPY,2026-10-26,680.20 두 행을 준비한다. Day 41~44에서는 이 seed를 바꾸며 실험한다. Airflow 연동은 Worker 이미지 안에도 같은 dbt 어댑터·프로젝트·profile을 배치해야 한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 41](../day41/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
from airflow.providers.standard.operators.bash import BashOperator

# 기존 DAG의 with DAG(...) 내부에 추가한다.
transform = BashOperator(
    task_id="dbt_build",
    bash_command="dbt build --project-dir /opt/airflow/dbt/market "
                 "--profiles-dir /opt/airflow/dbt/profiles "
                 "--select +mart_symbol_prices",
)
# 기존 load Task 객체와 연결: load_task >> transform
```

**예상 결과와 확인 기준:** Worker 안의 dbt --version·dbt debug 확인 후 Task가 build 로그와 종료 코드를 남긴다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. dbt가 포함된 Airflow 커스텀 이미지를 만들고 버전 목록을 기록한다.
2. 프로젝트 마운트와 호스트 DB 접근 주소를 확인하고 적재 → dbt_build를 연결한다.
3. 테스트 실패를 주입해 DAG도 실패하는지 확인한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day44/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

예제에서 지정한 Python 환경·현재 경로·패키지 버전을 확인한다. Task 내부나 이전 코드에 합치는 부분 예제는 주석의 실행 문맥을 먼저 준비한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
