## 1장. 개념 이해하기

완전성은 필요한 값이 있는지, 유일성은 키가 중복되지 않는지, 유효성은 허용 범위인지 확인한다. 참조 무결성과 최신성도 별도 차원이다. 계약에는 필드 이름뿐 아니라 단위·타임존·키·지연 허용 범위를 포함한다.

## 2장. 실습 준비

기존 Python 정제·PostgreSQL DW·dbt 프로젝트를 사용한다. 품질 오류는 별도 학습 배치에 넣고 Raw의 최초 샘플을 보존한다. 아래 SQL의 고정 CTE는 실제 운영 표를 변경하지 않는다. 코드·계약·규칙은 quality/ 아래에 정리한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 96](../day96/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```yaml
# quality/market_contract.yml: 학습용 자체 계약이며 실행 도구 설정은 아니다.
dataset: clean_market_prices
grain: [symbol, trade_date]
fields:
  symbol: {type: string, required: true}
  trade_date: {type: date, required: true}
  close_price: {type: decimal, required: true, min_exclusive: 0}
freshness:
  source_dataset: public.raw_market_prices
  source_field: collected_at
on_invalid_row: quarantine
on_missing_required_column: fail_batch
```

**예상 결과와 확인 기준:** 계약을 설명할 수 있고 실제 검사는 다음 수업에서 구현한다. YAML 파일 작성만으로 검증이 실행되지는 않는다.

`clean_market_prices`는 Day 10의 정제 view이며 `symbol`, `trade_date`, `close_price` 세 컬럼만 가진다. 최신성은 이 view에 없는 컬럼을 조회하는 대신 원천 `public.raw_market_prices.collected_at`으로 검사한다. 위 `freshness` 항목은 그 참조 대상을 명시한 자체 계약이다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 기존 Python·dbt·DB 제약 조건을 계약의 각 규칙에 대응시킨다.
2. NULL·중복·비양수·미등록 종목·갱신 지연에 대한 실패 기준을 적는다.
3. 경고·행 격리·배치 중단을 선택하는 근거를 작성한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day96/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설정 예제는 지정한 파일의 위치에 넣는다. 일부 설정만 보인 경우 기존 키에 병합하고 같은 최상위 키를 중복 작성하지 않는다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
