# Day 100. 오류 주입과 20주 리뷰

**20주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 99](../day99/README.md) · [Day 101 →](../day101/README.md)

이번 주에는 **데이터 품질 규칙과 실패 처리** 내용을 다룬다. 오늘은 품질 검사와 복구가 실제로 동작하는지 검증한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 품질 검사와 복구가 실제로 동작하는지 검증한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

정상 입력만 통과하는 모습을 보는 것으로 실패 감지 능력을 알 수 없다. 오류를 한 가지씩 주입하면 어느 검사가 잡는지 확인할 수 있다. 여러 오류를 한 번에 넣으면 앞선 실패 때문에 나머지가 검증되지 않을 수 있다.

## 2장. 실습 준비

기존 Python 정제·PostgreSQL DW·dbt 프로젝트를 사용한다. 품질 오류는 별도 학습 배치에 넣고 Raw의 최초 샘플을 보존한다. 아래 SQL의 고정 CTE는 실제 운영 표를 변경하지 않는다. 코드·계약·규칙은 quality/ 아래에 정리한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 96](../day96/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
사례                  기대 행동
NULL 가격             행 격리, 허용 비율 초과 시 배치 중단
중복 업무 키          정제 정책 적용 후 최종 중복 0건
필수 컬럼 누락        배치 중단
원천 수집 지연        최신성 경고 또는 공개 중단
수정 후 같은 배치 재실행 최종 키·가격 일치
```

**예상 결과와 확인 기준:** 각 사례에 실제 실패 로그·격리 건수·공개 상태·복구 후 결과를 대응시킨다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 4가지 오류를 분리된 입력으로 재현하고 검출 결과를 기록한다.
2. 하나의 오류를 고친 뒤 같은 구간 재실행을 확인한다.
3. 품질 규칙표·검증 코드·실패 처리·공개 조건을 20주 산출물로 묶는다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day100/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
