## 1장. 개념 이해하기

한 파일에서 다운로드·정제·저장을 모두 수행하면 오류가 어느 단계에서 났는지 찾기 어렵다. 함수가 맡을 책임과 입력·출력을 정하면 정제 함수를 파일이나 DB 없이도 검증할 수 있다.

부작용은 파일 생성이나 DB 변경처럼 함수 바깥의 상태를 바꾸는 동작이다. 정제 계산과 부작용을 분리하면 같은 입력의 결과를 비교하기 쉽다. 오늘은 Day 1 코드를 복사해 함수로 나누고 원본은 남긴다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
from decimal import Decimal, InvalidOperation

def parse_price(value):
    try:
        price = Decimal(str(value))
    except InvalidOperation:
        return None
    return price if price.is_finite() and price > 0 else None

for value in ["620.50", None, "N/A", "0", "NaN"]:
    print(repr(value), parse_price(value))
```

**예상 결과와 확인 기준:** 620.50만 Decimal 값이 되고 나머지는 None이다. 함수는 파일을 만들지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.
