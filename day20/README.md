## 1장. 개념 이해하기

단위 테스트는 작은 함수에 입력을 넣고 약속한 결과를 확인한다. 구현의 줄 순서를 그대로 따라 검사하기보다 N/A·None·NaN·0·음수 같은 의미 있는 경계를 고른다. 이렇게 해야 함수를 고쳐도 규칙을 유지하는지 확인할 수 있다.

파일 저장까지 확인하는 통합 검증은 별도로 둔다. 테스트가 통과했다는 이유로 API 연결이나 DB 적재도 검증된 것은 아니다. 오늘은 순수 정제와 파일 입출력 검증의 범위를 구분한다.

## 2장. 실습 준비

Python 3.11 이상을 사용하고 버전을 기록한다. 루트에서 `python -m venv .venv`로 가상환경을 만들고, 이후 Python 블록은 `dayNN/practice.py`로 저장해 `.\.venv\Scripts\python.exe .\dayNN\practice.py`로 실행한다. Python 표준 라이브러리부터 사용하며 Day 1 코드·샘플은 보존한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 16](../day16/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
import unittest
from decimal import Decimal

class PriceContractTest(unittest.TestCase):
    def test_price_is_finite_and_positive(self):
        for value in ["0", "-1", "NaN", "Infinity"]:
            with self.subTest(value=value):
                price = Decimal(value)
                self.assertFalse(price.is_finite() and price > 0)

if __name__ == "__main__":
    unittest.main()
```

## 4장. 직접 해볼 실습 과제

1. src의 정제 함수에 정상·무효·중복·최신 선택 기준 테스트를 연결한다.
2. 손상 JSON과 비어 있는 배열을 구분해 파일 입력 검증을 실행한다.
3. 4주 산출물로 src·의존성 목록·설정 예시·재실행 명령·격리 결과를 정리한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day20/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.
