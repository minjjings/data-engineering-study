# Day 113. 최소 배치 한 구간 연결

**23주 차 · 주간 3일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 112](../day112/README.md) · [Day 114 →](../day114/README.md)

이번 주에는 **통합 프로젝트 최소 배치와 스트리밍 확장** 내용을 다룬다. 오늘은 한 날짜 입력을 최종 마트까지 흐르게 한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 한 날짜 입력을 최종 마트까지 흐르게 한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

처음에는 작은 한 구간만 연결한다. 중간 파일을 확인하며 수집·정제·DW·마트를 붙이면 실패 위치를 좁히기 쉽다. 값을 수작업으로 수정하지 않고 명령 인자와 설정만으로 실행되게 한다.

## 2장. 실습 준비

기존 src·Spark·DW·dbt·Airflow를 사용한다. 설계는 docs/project에 모으고 가상 시장 가격 예제를 확장한다. 최소 배치 경로부터 검증하고 CDC는 별도 대상 표의 확장 경로로 둔다. 각 day 예제의 설계를 실제 코드로 연결하는 단계다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 111](../day111/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```json
{
  "batch_id": "2026-10-26-v1",
  "start": "2026-10-26", "end": "2026-10-27",
  "input_rows": 4, "valid_keys": 2,
  "raw_uri": "s3://YOUR_BUCKET/raw/market/batch=2026-10-26-v1/",
  "status": "planned"
}
```

**예상 결과와 확인 기준:** 예제 수치는 Day 1 Raw 4행을 쓸 때의 계획값이다. Spark의 정상 4행 샘플을 쓰면 기대 키 수를 다시 계산한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 날짜·batch_id·입력 경로를 받는 명령을 연결한다.
2. 한 구간의 단계별 키·가격·건수를 기록한다.
3. 최종 dbt source를 실제 DW로 분리해 옛 샘플을 읽지 않게 한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day113/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

YOUR_BUCKET 같은 예시 이름을 본인의 실습 환경 값으로 바꾼다. JSON 작성과 실제 서비스 적용·검증을 구분한다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.

- [ ] 따라 하기 예제의 실제 결과를 예상 결과와 비교했다.
- [ ] 직접 해볼 과제 세 개를 구현·실행하고 근거를 남겼다.
