## 1장. 개념 이해하기

네트워크 요청은 응답이 오지 않거나 HTTP 오류로 끝날 수 있다. 타임아웃은 한 요청을 무기한 기다리지 않게 하고 재시도 한도는 전체 실행을 끝낼 수 있게 한다. 인증 오류·잘못된 입력처럼 반복해도 해결되지 않는 실패는 즉시 알려야 한다.

재시도할 때마다 Raw 파일이나 DB 행이 중복 생성될 수 있으므로 수집과 적재의 재실행 정책을 함께 정한다. 오늘은 외부 API 대신 로컬 HTTP 서버로 성공·404·서버 종료를 재현한다.

## 2장. 실습 준비

Python 3.11 이상을 사용하고 버전을 기록한다. 루트에서 `python -m venv .venv`로 가상환경을 만들고, 이후 Python 블록은 `dayNN/practice.py`로 저장해 `.\.venv\Scripts\python.exe .\dayNN\practice.py`로 실행한다. Python 표준 라이브러리부터 사용하며 Day 1 코드·샘플은 보존한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 16](../day16/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
import json
from urllib.request import urlopen

# 별도 PowerShell: python -m http.server 8000 --directory day01/data
with urlopen("http://127.0.0.1:8000/raw.json", timeout=3) as response:
    rows = json.load(response)
print(len(rows))
```

**예상 결과와 확인 기준:** 저장소 루트에서 서버를 실행하면 Day 1 Raw 4건을 읽는다. 서버가 없으면 연결 오류가 발생해야 한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 최대 3회·대기 1초 후 재시도를 구현하고 시도 번호를 출력한다.
2. 없는 파일 404는 재시도하지 않고 서버 연결 오류만 재시도하도록 구분한다.
3. 성공·404·서버 종료 3가지 결과와 소요 시간을 기록하고 서버는 Ctrl+C로 종료한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day18/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.
