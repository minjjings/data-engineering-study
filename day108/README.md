# Day 108. 독립 DB 통합 테스트와 dbt 검증

**22주 차 · 주간 3일차 | 약 90~120분**

이번 주에는 **테스트·CI/CD와 재현 가능한 환경** 내용을 다룬다. 오늘은 CI의 새 DB에서 적재·변환 경로를 검증한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- CI의 새 DB에서 적재·변환 경로를 검증한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 1 | 개념과 준비 항목 확인 | 20분 |

## 1장. 개념 이해하기

서비스 컨테이너는 테스트용 DB를 새로 만든다. runner에서는 localhost의 매핑 포트, 다른 job 컨테이너에서는 서비스명으로 연결한다. 초기 DDL·입력·검증을 workflow에 명시해야 기존 로컬 상태 없이 실행할 수 있다.

## 2장. 실습 준비

4~5주 src와 tests, dbt 프로젝트가 준비되어 있어야 한다. 루트 requirements.txt에 실제 필요한 패키지와 버전을 정리한다. CI는 GitHub Actions의 독립 PostgreSQL17 서비스를 사용하고 로컬 실습DB·AWS 계정에 연결하지 않는다. workflow는 작성·로컬 확인 후 사용자가 push했을 때 원격 실행 결과를 확인한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 106](../day106/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```yaml
# 기존 job에 추가할 services 설정이다.
services:
  postgres:
    image: postgres:17
    env:
      POSTGRES_USER: de_user
      POSTGRES_PASSWORD: ci_local_only
      POSTGRES_DB: market_db
    ports: ["5432:5432"]
    options: >-
      --health-cmd "pg_isready -U de_user -d market_db"
      --health-interval 5s --health-timeout 5s --health-retries 10
```

**예상 결과와 확인 기준:** CI 서비스 준비 후 DDL과 입력 적재를 실행해야 표가 생긴다. 서비스 설정만으로 기존 데이터가 생성되지는 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. CI 전용 DSN과 dbt profile을 환경변수로 만들고 5432 포트를 사용한다.
2. DDL → 샘플 적재 2회 → 키·값 검증 → dbt build를 연결한다.
3. AWS 인증 없이 실행되는지 확인하고 성공·실패 로그를 남긴다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day108/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설정 예제는 지정한 파일의 위치에 넣는다. 일부 설정만 보인 경우 기존 키에 병합하고 같은 최상위 키를 중복 작성하지 않는다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
