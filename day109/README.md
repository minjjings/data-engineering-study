# Day 109. 배포 패키지와 되돌리기

**22주 차 · 주간 4일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 108](../day108/README.md) · [Day 110 →](../day110/README.md)

이번 주에는 **테스트·CI/CD와 재현 가능한 환경** 내용을 다룬다. 오늘은 검증한 버전을 식별하고 이전 버전으로 복구한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 검증한 버전을 식별하고 이전 버전으로 복구한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

CI는 검증이고 CD는 검증한 산출물을 환경에 적용하는 흐름이다. 코드를 되돌려도 DB 스키마와 이미 저장한 데이터는 자동 복구되지 않는다. 버전·호환성·재처리 계획을 함께 기록한다.

## 2장. 실습 준비

4~5주 src와 tests, dbt 프로젝트가 준비되어 있어야 한다. 루트 requirements.txt에 실제 필요한 패키지와 버전을 정리한다. CI는 GitHub Actions의 독립 PostgreSQL17 서비스를 사용하고 로컬 실습DB·AWS 계정에 연결하지 않는다. workflow는 작성·로컬 확인 후 사용자가 push했을 때 원격 실행 결과를 확인한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 106](../day106/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
release/
  version.txt       # commit id와 빌드 시각
  requirements.txt  # 실행 의존성
  src/              # 실행 코드
  dags/             # DAG
  dbt/              # 모델과 테스트
  deploy.md         # 적용·검증·되돌리기
```

**예상 결과와 확인 기준:** 검증한 commit으로 실제 패키지를 만들고 비밀값을 제외한다. 아래 구조는 직접 만들 산출물의 설계다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 별도 실습 디렉터리에 검증한 패키지를 만들고 정상 실행한다.
2. 다음 버전에 실패를 넣은 뒤 이전 패키지로 복구한다.
3. DB 변경 시 호환성·백업·재처리 필요 여부를 기록한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day109/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
