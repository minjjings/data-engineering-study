## 1장. 개념 이해하기

격리는 원본과 실패 사유를 별도 저장해 정상 흐름에서 분리하는 것이다. 필수 컬럼이 통째로 없거나 무효율이 임계값을 넘으면 일부 행만 제외하는 대신 배치 전체를 중단할 수 있다. 비율의 분모와 빈 배치 처리도 명시한다.

## 2장. 실습 준비

기존 Python 정제·PostgreSQL DW·dbt 프로젝트를 사용한다. 품질 오류는 별도 학습 배치에 넣고 Raw의 최초 샘플을 보존한다. 아래 SQL의 고정 CTE는 실제 운영 표를 변경하지 않는다. 코드·계약·규칙은 quality/ 아래에 정리한다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 96](../day96/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```python
rows = [{"symbol": "QQQ", "price": 620.50}, {"symbol": "SPY", "price": None}]
accepted, rejected = [], []
for row in rows:
    if row["price"] is None:
        rejected.append({"row": row, "reason": "missing_price"})
    else:
        accepted.append(row)
invalid_ratio = len(rejected) / len(rows) if rows else 0
print({"accepted": len(accepted), "rejected": len(rejected), "ratio": invalid_ratio})
if invalid_ratio > 0.1:
    raise ValueError("quality gate failed")
```

**예상 결과와 확인 기준:** 정상 1·격리 1·비율 0.5를 출력하고 의도적으로 실패한다. 정상 공개 전에 중단하는 예제다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 격리 파일에 batch_id·원본 경로·사유·규칙 버전을 저장한다.
2. 무효율 0%·10%·초과·빈 배치 경계를 실험한다.
3. 격리된 가격을 수정해 원본 배치와 연결된 재처리 기록을 남긴다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day98/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.
