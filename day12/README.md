## 1장. 개념 이해하기

트랜잭션은 여러 변경을 모두 반영하거나 모두 취소하는 단위다. 원본에서 목표 표로 옮기면서 처리 위치도 갱신한다면 두 변경이 함께 성공해야 한다. 적재만 되고 상태가 남으면 재처리가 필요하고 상태만 갱신되면 누락이 생긴다.

BEGIN으로 시작해 COMMIT하면 반영하고 ROLLBACK하면 취소한다. PostgreSQL에서 트랜잭션 내부 SQL이 실패하면 명시적으로 롤백해야 다음 작업을 정상 수행할 수 있다. 외부 파일 쓰기까지 자동으로 롤백되는 것은 아니다.

## 2장. 실습 준비

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```sql
CREATE TEMP TABLE lab_tx (id integer PRIMARY KEY, price numeric);
BEGIN;
INSERT INTO lab_tx VALUES (1, 620.50);
SELECT COUNT(*) FROM lab_tx;
ROLLBACK;
SELECT COUNT(*) FROM lab_tx;
```

**예상 결과와 확인 기준:** 롤백 전에는 1건이 보이고 롤백 후에는 0건이다. 현재 세션에서 보이는 중간 결과와 최종 커밋 상태를 구분한다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. ROLLBACK을 COMMIT으로 바꾼 별도 id 실습을 실행한다.
2. 하나의 트랜잭션에서 같은 PK를 두 번 넣어 오류를 만든 뒤 ROLLBACK하고 잔여 행을 확인한다.
3. 적재와 Watermark 상태 갱신을 같은 트랜잭션으로 묶는 의사 코드를 작성한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day12/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

SQL 실행 위치를 확인한다. 일반 PostgreSQL SQL은 psql에서, Athena SQL은 Athena에서, Jinja가 있는 모델 SQL은 dbt 모델 파일에서 실행한다. TEMP 테이블은 생성한 연결에서만 보인다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
