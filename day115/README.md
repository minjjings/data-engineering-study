# Day 115. CDC 확장과 23주 리뷰

**23주 차 · 주간 5일차 | 약 90~120분**

[전체 계획](../README.md) · [120일 목차](../README.md#day-index) · [← Day 114](../day114/README.md) · [Day 116 →](../day116/README.md)

이번 주에는 **통합 프로젝트 최소 배치와 스트리밍 확장** 내용을 다룬다. 오늘은 검증한 배치와 분리해 변경 이벤트 경로를 연결한다.

> 미리 작성한 교재다. 아래 예제·예상 결과는 학습 기준이며 실행을 완료했다는 뜻은 아니다. 과제에서 요구하는 코드·설정·결과는 직접 작성한다. 시장 가격은 가상 데이터다.

## 오늘의 학습 목표

- 검증한 배치와 분리해 변경 이벤트 경로를 연결한다.
- 예제의 입력과 결과를 비교하고 처리 기준을 자기 말로 설명한다.
- 직접 작성한 과제와 실행 근거를 남긴다.

| 순서 | 할 일 | 예상 시간 |
| --- | --- | --- |
| 1 | 개념과 준비 항목 확인 | 20분 |
| 2 | 예제 실행·입출력 확인 | 25~35분 |
| 3 | 직접 구현·실패 또는 경계 상황 실험 | 30~45분 |
| 4 | 결과 기록과 리뷰 | 15~20분 |

## 1장. 개념 이해하기

배치가 완료되면 CDC를 확장한다. 같은 표에 배치와 CDC가 쓰면 충돌 규칙이 필요하므로 별도 대상에서 최종 상태를 검증한다. 선택 확장을 생략해도 필수 배치의 검증은 완료해야 한다.

## 2장. 실습 준비

기존 src·Spark·DW·dbt·Airflow를 사용한다. 설계는 docs/project에 모으고 가상 시장 가격 예제를 확장한다. 최소 배치 경로부터 검증하고 CDC는 별도 대상 표의 확장 경로로 둔다. 각 day 예제의 설계를 실제 코드로 연결하는 단계다.

이전 학습일의 과제를 아직 구현하지 않았다면 해당 교재에서 먼저 준비한다. 문서 안의 파일명은 앞으로 작성할 산출물을 포함한다. 첫 사용 환경은 이번 주 첫 교재인 [Day 111](../day111/README.md)의 준비 항목도 확인한다.

## 3장. 예제로 따라 해보기

먼저 예상 결과를 읽고 어떤 입력이 어떤 이유로 남는지 생각한다. 아래 코드가 부분 예제라면 주석에서 지정한 파일·함수·이전 코드에 합친다.

```text
필수: 원본 경로·Parquet·DW·dbt·품질·공개
선택: CDC 원천 → Debezium → Kafka → cdc_target
확장 검증: snapshot·추가·수정·삭제·재시작
공통: 로그·지표·장애 대응 문서
```

**예상 결과와 확인 기준:** 실행 근거가 있는 완료 범위와 남은 범위를 구분한다. 선택 과제를 생략한 경우 완료로 표시하지 않는다.

화면 출력이나 성공 상태만으로 끝내지 않고, 오늘 목표와 직접 연결되는 건수·키·값·상태를 확인한다.

## 4장. 직접 해볼 실습 과제

1. 배치 한 구간의 전체 실행 근거와 누락 단계를 정리한다.
2. CDC를 선택했다면 원천·대상의 최종 상태를 비교한다.
3. 마지막 주의 정상·반복·재처리·오류·복구 목록을 확정한다.

작성한 코드·SQL·설정은 이 day 폴더 또는 과제에서 지정한 공통 디렉터리에 저장한다. 실행 기록은 `day115/notes.md`에 남긴다. 원본 예제와 별도 경로를 사용하고, 오류 입력·재실행으로 결과가 달라졌다면 그 이유도 기록한다.

## 5장. 막혔을 때 확인하기

설계·검증 시나리오 예제는 실행 결과와 대응시켜 읽는다. 실행 명령으로 입력하지 않고 본인이 구현한 코드·로그·결과와 대응시킨다.

예상 건수와 다르면 사용한 입력·필터·기존 상태부터 비교한다. 해결하지 못한 오류는 입력과 실행 명령, 오류 메시지를 함께 남긴다.
